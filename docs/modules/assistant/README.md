# Assistant

## Назначение

Модуль должен вести учебный диалог и интерпретировать источники через штатную Pi-сессию с ограниченным набором инструментов. Контракт фиксирует ревизию `f3bacd3`.

## Границы ответственности

Pi должен получать только custom study tools; встроенные инструменты, shell, расширения, skills, prompts, themes, AGENTS-файлы рабочей среды должны быть отключены через resourceLoader. Профиль владельца и тексты источников должны передаваться как данные, не инструкции.

Модель должна отвечать по-русски, использовать Europe/Moscow, не обрабатывать SmartLMS и вложения; сохранять один устойчивый id обязательства, вызывать list_tasks перед изменением и search_history при нехватке контекста. Для новых и изменённых обязательств должен требоваться update_task. Модель не должна выдумывать сроки/статусы/формулы, считать удаление сообщения отменой, приписывать полноту непроверенным сведениям или неразобранной истории.

При конфликте сроков модель должна сохранять ранний срок, disputed и готовить вопрос. Done и submitted должны оставаться различными статусами. Дата без времени должна считаться личной границей 00:00 указанной московской даты. Личные статусы и разрешение отправки нельзя получать из текстов источников. Вопрос в группу должен проходить propose_question, перенос расписания — propose_lesson_change и отдельное решение владельца через Study.

Допуск самостоятельного подключения чата должен ограничиваться относящимися к учёбе чатами, где личный аккаунт уже состоит. Инструкции источника не должны разрешать подключение постороннего чата; личные диалоги и вступление запрещены. Новые чаты доступны только для чтения. Проверка учебных правил должна использовать официальные hse.ru страницы, ссылки и учебный год; полноту нельзя заявлять без проверки всех личных дисциплин.

При неполном ответе на уточнение модель должна вызвать notify_owner. Новые тексты без важных учебных фактов не должны порождать уведомления. Ответ владельцу и сводка должны возвращаться финальным текстом, без дублирующего notify_owner.

Эти правила поведения модели не должны подменять техническую авторизацию операций: ownerTurn отдельно проверяет только переходы личных статусов; инструменты подключения/уведомления/создания черновиков не имеют дополнительного ownerTurn gate.
