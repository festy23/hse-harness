# Восстановление намерений работ

## Описание

Сверка незавершённых TaskOperation без повторного вызова модели.

## Запуск

`recoverTaskOperations` перед Scheduler.refresh в цикле `Синхронизация заданий`, интервал pollSeconds после завершения; общий source budget=120000 ms. Каждая Complete имеет calendarMutation budget=90000 ms, ограниченный общим ctx.

## Входные параметры

calendar, scheduler, store обязательны; ctx необязателен.

## Результат

void. Нефатальная ошибка отдельной операции после flush должна оставить её для будущей сверки и не проваливать весь цикл. Ошибки transaction/flush и fatal должны достигать вызывающего worker.

## Ресурсы

[TaskOperation](../operations/task-operation.md), Scheduler locks, Store.flush.

## Алгоритм работы

1. Пройти Object.values(taskOperations??{}), исключить notified/superseded, сгруппировать по taskId, сохраняя порядок операций.
2. Запустить максимум 4 обработчика групп. Busy taskId пропустить. Для остальных удерживать transaction(taskId) на обработку группы.
3. Последовательно вызвать Complete для каждой операции. На нефатальной ошибке вызвать Store.flush и прекратить обработку только этой группы. На fatal пробросить исключение из transaction.
4. Дождаться всех обработчиков. Из собранных ошибок выбрать первую fatal, иначе первую ошибку; если ошибок нет, вернуть void.

Отсутствующий writeAttempted у старого намерения должен считаться неизвестной прошлой попыткой. Recovery не должен повторять PUT, пока desired не обнаружен либо не создано разрешённое новое намерение.
