# Журнал документирования HSE Harness

## Задача и источники

По запросу владельца проекта документировано существующее поведение HSE Harness с использованием [writing-spec](../.agents/skills/writing-spec/SKILL.md) и отдельных агентов. Основа — исходники ревизии `f3bacd3`, [AGENTS.md](../AGENTS.md), [CONTEXT.md](../CONTEXT.md). Изменения реализации в задачу не входили.

Формальная документация начинается с [индекса](modules/index.md). Карта [покрытия](modules/coverage.md) связывает 106 исходных и конфигурационных файлов с контрактами; в ней присутствуют все 97 отслеживаемых файлов из src, runtime, bin, scripts, deploy и .github. Тесты использованы для проверки интерпретации поведения; их fixtures не превращены в новые продуктовые требования. Существующее архитектурное предложение не изменялось и не принималось за источник обязательного поведения.

## Распределение работы

| Исполнитель | Область | Результат |
|---|---|---|
| Основной агент | Core, Development, индекс, покрытие и навигация | Общие схемы, persistence, budgets, lifecycle, сборка, качество, CI, диагностические команды |
| spec_telegram_sources | Telegram Bot, Sources, legacy deploy compatibility | Bot API, outbox, callbacks, MTProto, IMAP, адаптеры совместимости |
| spec_study_assistant | Calendar, Study, Assistant | Провайдеры, календарные изменения, task recovery, approvals, scheduler, Pi и tools |
| spec_runtime_cli | Runtime, CLI | Установка, integrity, supervisor, обновления, onboarding, OAuth, systemd, импорт |

Все исполнители прочитали применимые инструкции writing-spec и соответствующие исходники. Автор Telegram-раздела дополнительно использовал Telegram skill и сверил протокол с официальной Bot API 10.3 от 24.08.2026. Автор Calendar проверил установленный tsdav 2.4.0 для точных DAV-запросов. Runtime и CLI проверены по реализации, в том числе по сценариям утраты activation ACK и глобальной установки.

## Принятые технические решения

- Девять модулей разделены по ответственности существующего приложения. Общая схема operations.json и доменные сущности описаны в Core; модули ссылаются на них.
- Для внутренних функций, CLI и IPC добавлен каталог operations; исходящие HTTP-вызовы находятся в http, фоновые циклы — в jobs.
- Постоянного публичного HTTP/gRPC сервера нет. Временный loopback Google OAuth callback описан отдельно в CLI.
- PostgreSQL и Redis отсутствуют; файловые ресурсы описаны в database/README.md. DBML/SVG для несуществующей SQL-схемы не создавались.
- Параметры, порядок записи, отмена, дедупликация и неизвестный исход внешнего действия описаны как реализованы. Документация не вводит дополнительные retry, транзакции или гарантии exactly-once.
- Объяснения процесса работы и результатов проверок оставлены в этом журнале, вне нормативных контрактов.

Новых решений, меняющих наблюдаемое поведение, не принималось. Вопросов владельцу о новой бизнес-логике не потребовалось: задача ограничена текущей реализацией. Нерешённых вопросов или намеренно оставленных незавершённых разделов нет.

## Фактическая сверка

Авторы сверили свои документы с исходниками. Дополнительно spec_telegram_sources проверил весь Core и уточнил отсутствие legacy profile default, границы обработки фоновых ошибок, повторные IPC ACK, notice sequence, проверку загружаемого состояния и тексты напоминаний. Spec_study_assistant отдельно сверил Development, включая eval и команды CI. Основной агент проверил структуру, покрытие и навигацию, выборочно сверил критические контракты с исходниками.

Это самопроверка и фактическая сверка документации. Независимое ревью по отдельному reviewing-spec не выполнялось: этот скилл в проект не установлен.

## Проверки

- Карта покрытия: все 97 отслеживаемых файлов реализации/инфраструктуры и 9 корневых файлов конфигурации/запуска имеют ссылки на контракты.
- Проверены локальные Markdown-ссылки и anchors, доступность всех страниц из индекса, наличие README/database/caches/settings каждого модуля и обязательных разделов HTTP/jobs.
- Проверены trailing whitespace и `git diff --check`; новые неотслеживаемые Markdown-файлы дополнительно прочитаны файловым сканером, поскольку обычный git diff их не включает.
- Подтверждено отсутствие изменений в src, runtime, scripts, deploy, bin, test, package/config/CI и локальных скиллах репозитория.
- npm format/check/test:e2e и обращения к живым аккаунтам не выполнялись: изменена только документация; AGENTS.md допускает проверку ссылок и содержимого для этого случая.
- Генерация схем или других производных визуальных артефактов не требовалась.

Механические проверки выполнены временными Python-скриптами, не добавляющими зависимости проекта: `/private/tmp/hse-check-docs.py` и `/private/tmp/hse-doc-coverage.py`. Воспроизводимые правила проверок перечислены выше; временные файлы не входят в поставку.
