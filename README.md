# HSE HARNESS

**Учебный ассистент, с которым можно общаться в Telegram.** Он читает выбранные учебные чаты и Яндекс Почту, собирает задания, напоминает о сдаче и ведёт отдельный календарь дедлайнов. Ты подключаешь свои аккаунты и указываешь свой курс, группу и предметы.

## Как выглядит настройка

![Настройка HSE HARNESS в терминале: логотип, меню и заполнение учебного профиля](https://raw.githubusercontent.com/festy23/hse-harness/main/docs/assets/cli-setup.gif)

Запись настоящего CLI: выбор раздела, заполнение демонстрационного профиля и сохранённые настройки. Все данные в примере вымышленные.

## Что умеет ассистент

- Читать текст из выбранных Telegram-групп, каналов и папок Яндекс Почты.
- Находить задания и сроки, замечать переносы и отмены.
- Учитывать расписание из Google, Яндекс или iCloud Calendar; хранить дедлайны в отдельном календаре.
- Присылать сводки в **10:00 и 20:00 по Москве**, напоминать **за три дня, сутки и час**. Срочные изменения сообщать сразу, в том числе ночью.
- Различать «сделал» и «сдал»: готовая, но ещё не отправленная работа продолжает требовать сдачи.
- Предлагать вопрос в учебный чат, если срок непонятен. Отправлять его от твоего аккаунта после твоего подтверждения.

Сейчас ассистент работает с текстом. SmartLMS, вложения, скриншоты и голосовые не обрабатываются; выполнение домашних заданий в эту версию не входит. Найденные сроки стоит сверять: модель может ошибиться или не увидеть задание за пределами подключённых источников.

## Установить и запустить

Понадобится [Node.js](https://nodejs.org/) **22.19 или новее** с npm:

```sh
npm install -g @ivan-boss/hse-harness
hse-harness
```

Откроется меню **HSE HARNESS**. Pi и остальные библиотеки устанавливаются вместе с пакетом; Git и сборка проекта для этого не нужны.

Для разового запуска меню можно использовать:

```sh
npx @ivan-boss/hse-harness
```

Для постоянного сервиса на VPS установи пакет через `npm install -g`.

Настройки, авторизация и память хранятся в **`~/.hse-harness/`**, отдельно от приложения. Посмотреть точные пути: `hse-harness paths`. Другой каталог можно задать переменной `HSE_HARNESS_HOME`.

Если уже настроил агента из репозитория, сначала останови старый процесс, затем перенеси состояние в ещё не существующий каталог:

```sh
hse-harness import /путь/к/hse-harness
hse-harness status
```

Импорт сохраняет профиль, выбранные источники, авторизацию, очередь и историю Pi, исправляет путь к сессии и исключает старый PID и тестовые данные. Существующую установку он не перезаписывает. Если `~/.hse-harness/` уже существует, выбери другой пустой путь через `HSE_HARNESS_HOME`.

Для разработки из исходников:

```sh
git clone https://github.com/festy23/hse-harness.git
cd hse-harness
npm run harness
```

На macOS/Linux также доступен `./hse`. Данные запуска из исходников по-прежнему остаются в каталоге репозитория.

## Подключить свои аккаунты

В меню выбери **«Настроить всё по шагам»** или открой нужный раздел отдельно. Каждый законченный раздел сохраняется; остальные можно настроить позже.

| Раздел | Что потребуется |
| --- | --- |
| 👤 Информация о тебе | Имя, вуз, программа, группа, курс, учебный год и список предметов. Майнор и НИС можно добавить в том же разделе. |
| ✈️ Telegram | Собственный бот от [BotFather](https://t.me/BotFather), его токен и `API ID` / `API hash` с [my.telegram.org](https://my.telegram.org). CLI выполнит вход в личный аккаунт и предложит выбрать чаты и каналы. |
| ✉️ Яндекс Почта | Адрес учебного ящика, включённый IMAP и [пароль приложения](https://id.yandex.ru/security/app-passwords) типа «Почта». |
| `>_` Подписка и модель | Вход через ChatGPT и выбор доступной модели. Сейчас поддерживается подписочный вход OpenAI; CLI подскажет, как авторизоваться. |
| 📅 Расписание и дедлайны | Два разных календаря: один с расписанием, второй для событий ассистента. Можно выбрать iCloud, Яндекс или Google, в том числе разных провайдеров для этих двух ролей. |

Для **iCloud** нужен адрес Apple Account и [пароль приложения](https://account.apple.com/). Для **Яндекс Календаря** — отдельный пароль приложения типа «Календарь». Для **Google** — OAuth client ID и client secret. [Подробная инструкция по подключениям](https://github.com/festy23/hse-harness/blob/main/docs/technical-guide.md#подключения).

**Управление:** ↑ ↓ — выбрать, Enter — подтвердить, пробел — отметить чат. Ctrl+C отменяет текущий раздел; в главном меню завершает CLI. ✅ означает, что настройки сохранены, ❌ — что раздел ещё нужно настроить. Пункт **«Разрешённые Telegram-чаты»** показывает, какие источники выбраны для чтения и где разрешены вопросы после подтверждения.

## Начать пользоваться

1. После настройки выбери **«Запустить бота»** в CLI.
2. Открой личный чат со своим ботом в Telegram и нажми **Start**.
3. Дождись разбора доступной истории выбранных источников. Сейчас начальная дата — **1 сентября 2026 года**; найденные задания нужно сверить и отметить уже сданные.
4. После сверки отправь **`/ready`**, чтобы включить напоминания.

Пока процесс работает, можно общаться обычными сообщениями:

```text
Какие задания нужно сдать на этой неделе?
Сделал домашку по алгебре, но ещё не сдал.
Сдал домашку по алгебре.
Добавь учебный чат https://t.me/hsetestingseminar.
Подключи чат -1001234567890 для анализа истории.
Какие Telegram-чаты ты сейчас читаешь?
```

| Команда боту | Что покажет или сделает |
| --- | --- |
| `/start` | Откроет диалог и покажет, как пользоваться помощником. |
| `/help` | Все доступные команды с пояснениями. Работает и во время подключения модели и календарей. |
| `/tasks` | Работы с известными сроками в календаре. |
| `/status` | Состояние подключений, очередь сообщений и готовность напоминаний. |
| `/updates` | Покажет текущую и последнюю версии, настройку автообновления и кнопку «Обновить» при постоянном запуске npm-установки. |
| `/ready` | Включит напоминания после начальной сверки. |

Основной диалог идёт **через аккаунт бота**. Твой личный Telegram-аккаунт нужен для чтения учебных источников и отправки согласованных вопросов. Изменения календаря расписания тоже требуют подтверждения; свой календарь дедлайнов ассистент обновляет автоматически.

Учебные чаты можно добавлять в разговоре с ботом по ссылке на чат/сообщение, пригласительной ссылке, `@username` или ID. Ассистент проверит, что личный аккаунт уже состоит в группе или канале, сохранит источник и начнёт загружать историю с 1 сентября 2026 года при следующем цикле чтения. Перезапуск не требуется; повторное добавление не создаёт дубликат. Если доступа нет, бот сообщит об ошибке и не станет вступать в чат. Добавленные агентом источники получают только право чтения.

## Запуск, обновление и остановка

```sh
hse-harness start           # запуск в текущем терминале
hse-harness status          # сохранённые настройки
hse-harness telegram-chats  # разрешённые чаты
```

`status` в терминале показывает сохранённые данные; реальные подключения проверяет `/status` в боте. При ручном запуске держи процесс открытым; **Ctrl+C** останавливает его.

На Linux с systemd, под отдельным пользователем бота с доступом к sudo:

```sh
hse-harness service install
hse-harness service status
hse-harness service logs
```

Сервис продолжает работать после закрытия SSH и запускается при перезагрузке VPS. Команда установки попросит sudo для записи системного сервиса, сам бот работает от текущего непривилегированного пользователя. Для предварительного просмотра: `hse-harness service install --dry-run`.

Начиная с версии 0.2.0, постоянная npm-установка запускает управляющий процесс. Чтобы применить следующую совместимую версию, достаточно:

```sh
npm update -g @ivan-boss/hse-harness
hse-harness updates status
```

Бот сам подготовит новую версию, завершит текущую операцию и переключится с короткой паузой. При ошибке запуска вернётся прежний код с актуальной памятью. Установленная и работающая версии показаны отдельно. Применение новой версии начинается после команды npm или подтверждения кнопкой в Telegram.

**Первый переход с уже работающей 0.1.0 требует одной остановки:**

```sh
hse-harness service stop
npm install -g @ivan-boss/hse-harness@latest
hse-harness service install
```

Для локального перехода останови прежний процесс через Ctrl+C, установи новую версию и выполни `hse-harness start`. После этого следующие `npm update -g` подхватываются автоматически. `npx`, запуск из исходников и `hse-harness run` остаются обычным запуском. После изменения профиля, источников или календарей перезапусти бота.

Бот проверяет `latest` в npm раз в час. Если доступна новая стабильная версия, он присылает владельцу предложение с кнопкой **«Обновить»** — не чаще одного раза за 24 часа, пока работающая версия не обновится. `/updates` показывает текущую работающую версию, последнюю доступную в npm и состояние автообновления. Там же можно включить или выключить его кнопкой. Настройка сохраняется при перезапуске. При недоступном npm отображается последняя известная версия, а переключатель продолжает работать. Кнопки доступны только в личном диалоге владельца, даже если модель или учебные подключения недоступны.

**Автообновление по умолчанию выключено.** После явного включения бот сам устанавливает новые совместимые версии и передаёт их supervisor для безопасного переключения. Отключение запрещает новые автоматические установки; уже начатое применение завершается безопасно. Неудачная или помещённая в карантин версия автоматически повторно не устанавливается: остаются ежедневное напоминание и ручная кнопка. Проверка `/updates` не откладывает очередное ежедневное уведомление. Эта настройка управляет скачиванием новых выпусков из npm; CLI `updates enable` управляет применением уже установленных выпусков и сам по себе не включает автоматическое скачивание. CLI `updates disable` также выключает автообновление.

После нажатия бот проверяет архив и совместимость, устанавливает выбранную версию и передаёт переключение supervisor. Повторные нажатия не создают ещё одну установку. При успешном переключении приходит уведомление; при сбое прежняя версия продолжает работать, и попытку можно повторить. Память и очередь сохраняются. Если автоматическое применение выключено, кнопка временно разрешает его для этой попытки и затем возвращает прежнюю настройку. Несовместимый выпуск требует обслуживания через CLI.

Управление: `hse-harness updates disable`, `enable`, `retry`, `rollback`. Ручной откат не откатывает память и не отменяется наблюдателем сразу после выполнения. Несовместимая смена формата данных, Node или supervisor требует отдельного обслуживания. Настройки и память сохраняются в личном каталоге; для выпусков и временной установки нужен дополнительный запас диска — от 750 МБ.

Версия **0.3.0** требует supervisor **1.0.1**. Для первого перехода дождись завершения текущих операций, останови сервис, установи `@ivan-boss/hse-harness@0.3.0` и выполни `hse-harness service install`. Дальнейшие совместимые обновления снова применяются автоматически. Команды перехода приведены в [описании выпуска](docs/releases/0.3.0.md). Контракты отмены, ограничения и проверки описаны в [спецификации асинхронного выполнения](docs/async-hardening-spec.md); локальное измерение задержек запускается командой `npm run benchmark:async`.

[Подробнее о переносе и размещении на VPS](https://github.com/festy23/hse-harness/blob/main/docs/technical-guide.md#vps).

## Данные и доступ

Бот принимает команды только от настроенного владельца в личном чате. Модель получает сообщения из выбранных учебных источников; учитывай это при выборе чатов и папок.

Настройки и доступы хранятся локально. В личном каталоге находятся `.env`, `config.local.json`, `secrets/` и `data/`. Эти данные не входят в npm-пакет и исключены из Git: каждый человек подключает собственные аккаунты. Для резервного копирования сохрани личный каталог. При переносе на сервер копируй эти файлы и каталоги по SSH, исключая `data/service.lock`, затем используй команду импорта. Не публикуй их вместе с репозиторием.
