# Виды памяти AI-агента: карта понятий и чтение

Проверено 3 октября 2026 года. Это вводный обзор терминов, а не решение об архитектуре проекта. Свежие разработки, версии реализаций и новые проверки рассмотрены отдельно в [актуальном исследовании](agent-memory-latest.md).

## Две разные классификации

**По области использования:** кратковременная память относится к текущему диалогу или задаче; долговременная доступна между диалогами. В LangGraph даже кратковременное состояние можно сохранять в базе и возобновлять после перезапуска. Поэтому «кратковременная» не означает «обязательно исчезает при выключении». [Официальный Memory overview](https://docs.langchain.com/oss/python/concepts/memory).

**По содержимому:** CoALA выделяет рабочую память и долговременные семантическую, эпизодическую и процедурную памяти. Это концептуальная схема; названия и границы в разных системах могут отличаться. [CoALA, §4.1](https://arxiv.org/html/2309.02427v3#S4.SS1).

| Вид | Что означает | Пример для учебного ассистента |
|---|---|---|
| Рабочая, working memory | Информация, используемая в текущем шаге: запрос, активная цель, найденные данные, результаты инструментов | Сейчас составляем список заданий на неделю |
| Семантическая, semantic memory | Факты и знания | Предметы студента, формула накопа, предпочтения по уведомлениям |
| Эпизодическая, episodic memory | События и прошлый опыт | Преподаватель объявил перенос; агент уточнил срок и получил ответ |
| Процедурная, procedural memory | Правила и способы выполнения действий | Как проверять конфликт сроков, как составлять сводку |

Определения таблицы основаны на [CoALA, §4.1](https://arxiv.org/html/2309.02427v3#S4.SS1); примеры — наша иллюстрация. В CoALA рабочая память шире одного prompt: она может быть структурой данных между вызовами LLM, а в очередной запрос модели попадает только ее часть. Процедурная память может включать код и знания в весах модели; в практических агентных системах инструкции и навыки также описывают этим термином. [LangChain: Procedural memory](https://docs.langchain.com/oss/python/concepts/memory#procedural-memory).

## Что не следует смешивать

- **Контекст модели** — сведения, переданные в конкретный вызов. Сохраненный архив автоматически в него не попадает: информацию надо извлечь. MemGPT специально организует перенос данных из внешней памяти в ограниченный контекст. [MemGPT, §2](https://arxiv.org/html/2310.08560v2#S2).
- **Persistence** — сохранение данных между запусками. Это свойство хранения, которое может применяться и к состоянию диалога, и к долговременным фактам. [LangChain Memory overview](https://docs.langchain.com/oss/python/concepts/memory).
- **Retrieval / RAG** — получение нужных сведений для ответа; **векторный индекс** — один из способов поиска. Семантическая память означает знания, а семантический поиск — поиск по смыслу. SQL, текстовый поиск и поиск по векторам могут обслуживать разные виды памяти. [LangChain: Semantic memory](https://docs.langchain.com/oss/python/concepts/memory#semantic-memory), [CoALA, §4.3](https://arxiv.org/html/2309.02427v3#S4.SS3).
- **Compaction** — управление растущим контекстом, например посредством резюме. Это механизм, не отдельный вид памяти. Сжатие контекста не обязательно удаляет архив: в Letta старые сообщения после compaction остаются доступны через API и инструменты поиска. [Letta: Stateful agents, Messages](https://docs.letta.com/v1-sdk/concepts/stateful-agents#messages).

**Применение к нашему обсуждению:** «учебное состояние» — название данных приложения, а не еще один общепринятый когнитивный тип памяти. Актуальный дедлайн можно считать фактом, историю переносов — событиями, правило проверки переносов — процедурой. База знаний и реестр заданий могут принадлежать одной долговременной памяти, но иметь разные схемы и запросы. Это наше сопоставление понятий, а не требование источников.

## Порядок изучения

1. [LangChain Memory overview](https://docs.langchain.com/oss/python/concepts/memory) — начать здесь: кратковременная/долговременная память, факты/опыт/инструкции, запись и поиск.
2. [CoALA](https://arxiv.org/html/2309.02427v3) — сначала §4.1 «Memory» и §4.3 «Retrieval actions»: концептуальная карта, применимая независимо от фреймворка.
3. [MemGPT](https://arxiv.org/html/2310.08560v2) — §2 и рисунки: как ограниченный контекст связан с большой внешней памятью.
